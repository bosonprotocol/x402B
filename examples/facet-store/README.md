# facet-store

A minimal TypeScript **buyer agent** for a Facet-powered store: it browses the catalog and
completes a **full purchase** — paying USDC into **Boson Protocol escrow** with the **x402B**
scheme, over the **UCP checkout-session** endpoints.

Unlike the other examples in this folder, this one is a **CLI buyer**, not a service: there is
no Dockerfile and it isn't part of the e2e docker stack. It talks to a real, externally-hosted
Facet store — `my-boson-shop-2.bptest.technology`, backed by a Facet terminal at
`https://my-boson-shop-2.sandbox.facet.llc` (sandbox → Base Sepolia **test** USDC).

📖 **[AGENT-PURCHASE-FLOW.md](AGENT-PURCHASE-FLOW.md)** is the walkthrough — what each step does
and why. This README is the map of the package and how to run it.

## What's here

| File | What it is |
|---|---|
| [src/purchase.ts](src/purchase.ts) | **The reference example.** The whole purchase flow in one self-contained file, no shared helpers. Paired with [AGENT-PURCHASE-FLOW.md](AGENT-PURCHASE-FLOW.md). |
| [src/purchase-ucp.ts](src/purchase-ucp.ts) | Same flow, instrumented and configurable: prints every request/response, env-selectable product, ship-to and network (incl. mainnet), and polls for on-chain commit confirmation before redeeming. Use it to debug. |
| [src/agent.ts](src/agent.ts) | Catalog-only agent: SDK discovery (`/.well-known/agents.txt`) + `health` / `capabilities` / `search`. No purchasing. |
| `ucp-profile.json` | Your **public** UCP profile (public key only) — generated by `--init`, git-ignored. Publish it at a public HTTPS URL you control. |
| `.facet-agent-key.json` | Your **private** ES256 signing key — generated by `--init`, git-ignored. Never share it. |
| [.env.example](.env.example) | Copy to `.env` (git-ignored) and fill in. |

`.env`, `.facet-agent-key.json` and `ucp-profile.json` are resolved relative to this
package's root — one level up from the scripts in `src/`.

```bash
pnpm install     # from the repo root
pnpm start       # src/agent.ts        — browse the catalog
pnpm buy         # src/purchase.ts     — the purchase flow (dry run by default)
pnpm buy:ucp     # src/purchase-ucp.ts — same, verbose + more knobs
```

Run the `pnpm start` / `buy` / `buy:ucp` scripts from this directory, or from anywhere in the
monorepo with `pnpm --filter @bosonprotocol/x402-example-facet-store <script>`.

## Prerequisites

Node 22+ (the monorepo's `engines` floor), `pnpm install` at the repo root, and three things
(see [AGENT-PURCHASE-FLOW.md → Requirements](AGENT-PURCHASE-FLOW.md#requirements--three-things-the-agent-needs)):

1. **A funded buyer wallet** — any EVM key, funded with USDC on the store's network.
   **No ETH needed:** the on-chain commit is gasless for the buyer.
2. **Your own agent identity** — an ES256 key plus a **published UCP profile**. This is a
   prerequisite, not part of the run: the checkout endpoints authenticate you by
   [RFC 9421](https://www.rfc-editor.org/rfc/rfc9421) request signature, and the store fetches
   your public key from the profile URL to verify it. The store issues you nothing here.
3. **A KYA token** for catalog reads — the sandbox mints test tokens from a helper endpoint;
   the scripts do that automatically.

### One-time setup — generate and publish your identity

Put your wallet key in `.env` first — it is git-ignored, so the key stays out of your shell
history and out of the process list:

```bash
cp .env.example .env   # then set BUYER_PRIVATE_KEY in it
pnpm buy --init
```

This writes `.facet-agent-key.json` (**private**, git-ignored) and `ucp-profile.json` (public)
in this directory, and prints your wallet address. Then:

- **Publish `ucp-profile.json`** at any public HTTPS URL you control — a GitHub Gist **raw** URL
  is enough (prefer the revision-pinned form, `…/raw/<sha>/ucp-profile.json`, so it doesn't
  redirect). It does *not* go on the store's site, and no `/.well-known` route is needed.
- **Fund the printed address** with USDC on the target network (Base Sepolia test USDC for the
  sandbox).
- Add `UCP_PROFILE_URL` to `.env` (`BUYER_PRIVATE_KEY` is already in there).

## Run the purchase

```bash
# dry run — prices and signs everything locally, moves nothing
pnpm buy

# for real — commits USDC into escrow, then stores the signed redeem
SETTLE=1 pnpm buy
```

Config comes from the environment or a `.env` file in this directory (real env vars win).
`src/purchase.ts` reads:

| Variable | Meaning |
|---|---|
| `BUYER_PRIVATE_KEY` | Wallet key (hex, with or without `0x`). Funds and signs the payment. **Required.** |
| `UCP_PROFILE_URL` | Public URL of your published `ucp-profile.json`. **Required** (except for `--init`). |
| `SETTLE` | `1` to commit + redeem for real; unset = dry run. |
| `MAX_USDC` | Spend cap, in USDC (default `20`). |
| `TERMINAL` | Store terminal URL (default: the sandbox). |
| `RPC` | RPC endpoint (default: `https://sepolia.base.org`). |
| `AID` | Agent id for the sandbox KYA mint (default `agent:my-tester`). |

`src/purchase-ucp.ts` reads all of the above plus `NETWORK` (`base-sepolia` / `base`),
`PRODUCT_ID`, `QTY`, the `SHIP_*` fields, `COMMIT_CONFIRM_*` polling knobs, and `SITE_ID` /
`RAIL_ID` / `USDC_ADDRESS` / `BOSON_SUBGRAPH_URL` overrides — all documented in
[.env.example](.env.example).

### The flow

1. **Browse** — `client.search()` with a freshly-minted KYA token; picks the cheapest product.
2. **Create checkout** — `POST /ucp/v1/checkout-sessions` (RFC 9421 signed) → the store prices
   goods + shipping + tax and returns a **seller-signed Boson escrow offer** (network, USDC
   amount, escrow address), which the script validates with `parseEscrowPaymentRequirements`.
3. **Authorize** — the wallet signs an **ERC-3009** spend authorization locally. Nothing is
   broadcast; no money moves. The script also checks the wallet balance and the `MAX_USDC` cap.
4. **Commit** — `POST /ucp/v1/checkout-sessions/{id}/complete` (signed) with the
   `boson_commit_authorization` credential. The store's facilitator relays it **on-chain**,
   locking the USDC in escrow, and returns the Boson `exchange_id` (state `COMMITTED`).
   Gated behind `SETTLE=1`.
5. **Redeem** — the agent signs the Boson redeem (`x402b.signAction`) and hands it to the store
   via `POST /ucp/v1/checkout-sessions/redeem`. The store submits it on-chain **on fulfillment**,
   which is what releases the escrow to the seller (`redeemMode: "commit-only"`) — so the buyer
   stays protected until then.

## Going to production

- Point `TERMINAL` at the live store (e.g. `https://my-boson-shop-2.facet.llc`).
- Switch to the store's production network — `NETWORK=base` for `src/purchase-ucp.ts`; in
  `src/purchase.ts` the chain and USDC address are constants near the top — and fund the wallet
  with **real** USDC.
- Obtain a **real KYA token** from the store's KYA issuer instead of the sandbox test helper.
  The terminal's `kya-issuers` allowlist is managed by Facet and can't be set from the shop
  side, so a self-signed KYA JWT will not be accepted. (This applies to KYA only — the checkout
  signature genuinely *is* your own key.)
- Keep the machine clock accurate: skew makes both the request signature and the payment
  authorization expire (`signature_stale` / ERC-3009 `validBefore` expired).

## Key packages

| Package | Role |
|---|---|
| [`@bosonprotocol/x402-client`](../../typescript/packages/client) | Signs the ERC-3009 authorization and the Boson commit/redeem meta-txs (`handle402`, `signAction`). |
| [`@bosonprotocol/x402-core`](../../typescript/packages/core) | `fetchTokenDomain` (reads the token's EIP-712 domain on-chain) and `parseEscrowPaymentRequirements`. |
| `@facet-llc/client` | Terminal client used by the purchase scripts (`search`, `quote`); re-mints a single-use KYA token per request. |
| `@facet-llc/sdk-node` | `discoverAndConnect` — terminal discovery, used by `src/agent.ts`. |
| `viem` | Wallet signer (`privateKeyToAccount`) and chain reads. |

RFC 9421 request signing is hand-rolled with `node:crypto` (see `signedHeaders()` in
[src/purchase.ts](src/purchase.ts)) — no library needed.
